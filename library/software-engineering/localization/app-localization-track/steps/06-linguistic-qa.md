# Step 6: Linguistic QA and release

1. Plan in-context review by a native speaker on a staging build: key flows, emails and store listing, with a bug template (screen, string key, issue, suggested fix, severity).
2. Run functional checks in the target locale: missing keys, fallbacks, formats, layout and, if relevant, direction.
3. Define the release gate (for example no open critical or major bugs and all checkout and legal strings reviewed) and a rollout behind a flag or to a small audience first.
4. List what the team must verify outside engineering (legal text review, store requirements, support coverage).

Sections: QA plan, Release gate, Rollout, Open items.
