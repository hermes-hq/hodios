When you write or change code in this Symfony app:

**Know the project first**
- Check the Symfony version in `composer.json` and the bundles installed (API Platform, Messenger, Security, Doctrine). Prefer PHP attributes (`#[Route]`, `#[ORM\Entity]`, `#[Assert\...]`) if the project uses them, and follow the existing directory layout under `src/`.

**Services and DI**
- Rely on autowiring and autoconfiguration. Inject dependencies through the constructor (readonly promoted properties); never fetch services from the container (`$this->container->get`) or make services public to reach them.
- Bind scalar config with `#[Autowire('%param%')]` or `services.yaml` `bind`, not by reading `$_ENV` in services.
- Keep services stateless; per-request data does not live in service properties.

**Controllers**
- Controllers stay thin: map the request (`#[MapRequestPayload]`, forms or a DTO), call a service, return a response. No Doctrine queries or business rules inline.
- Use `#[IsGranted]` or `denyAccessUnlessGranted` with a voter for every action on a resource. Put ownership and permission rules in voters, not in `if` checks scattered across controllers and templates.

**Doctrine**
- Put queries in repository methods with descriptive names (`findActiveForCustomer`). Use the QueryBuilder or DQL with parameters; never concatenate input into DQL or SQL.
- Avoid N+1 queries: join and select relations you will use, and paginate list queries.
- Change the schema only with Doctrine migrations generated by `make:migration` and reviewed before committing. Never edit a migration that has run on a shared environment.
- Call `flush()` once per unit of work, in the service, not inside loops or entity methods. Keep entities free of service dependencies.

**Validation and forms**
- Put validation rules as constraints on DTOs or entities (`#[Assert\NotBlank]`, `#[Assert\Length]`), and validate with the validator or form. Do not hand-roll checks that constraints cover.
- Keep CSRF protection on for browser forms.

**Async and events**
- Send slow or retryable work (emails, webhooks, image processing) through Messenger to an async transport, with a message class carrying ids, not entities. Handlers re-load data and are idempotent.
- Use event subscribers for cross-cutting reactions; keep them small and do not hide core business flow in listeners.

**Configuration and secrets**
- Store secrets in the Symfony secrets vault or real environment variables, not committed `.env` files. `.env` holds non-secret defaults only; `.env.local` is never committed.
- Production runs with `APP_ENV=prod`, `APP_DEBUG=0`, and a warmed cache.

**Templates and output**
- Rely on Twig auto-escaping; use `|raw` only for trusted, sanitised content. Generate URLs with `path()` and `url()`.
- Use the Serializer with groups or explicit DTOs for JSON; never serialise entities wholesale.

**Before you finish**
- Run `bin/console lint:container`, PHPStan or Psalm at the project's level, and PHPUnit (including a `WebTestCase` for controllers you changed). Run `doctrine:schema:validate` after entity changes. Say what you ran.
